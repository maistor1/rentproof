# Next.js 16 route handlers in RentProof

RentProof pins `next@16.4.0`. Several things changed after Next 13/14, and code
written from memory tends to break on them. The installed docs are the source of
truth: `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/route.md`
and `01-app/01-getting-started/15-route-handlers.md`. Read them when something
here doesn't cover your case.

## The rules that bite

**Params are a promise.** Since v15, `context.params` must be awaited. Type it
with the global `RouteContext` helper, which takes the route literal:

```ts
export async function GET(_req: Request, ctx: RouteContext<"/api/rentals/[rentalId]">) {
  const { rentalId } = await ctx.params;
}
```

`RouteContext` is generated by `next dev`, `next build` or `next typegen`. If
TypeScript says it doesn't exist, run `npx next typegen` rather than hand-typing
the params.

**GET is not cached.** Route handlers run per request by default (changed in
v15). Don't add `export const dynamic = "force-dynamic"` to routes; it's
redundant. Pages are different: `src/app/page.tsx` reads files at render time
and keeps `force-dynamic` so it isn't prerendered at build.

**Runtime is Node.js.** `nodejs` is the default and `edge` is deprecated. We
need Node for `node:fs` and `sharp`, so never set `runtime = "edge"`.

**Use web Request/Response.** Return `Response.json(data, { status })`. There is
no `res` object and no `NextResponse` requirement. Use `NextRequest` only if you
need `nextUrl` or cookies.

## Patterns used in this repo

### JSON body with validation

Bodies are untrusted. Parse, check the shape, and return 400 with a short
message instead of letting a `TypeError` become a 500.

```ts
export async function POST(req: Request) {
  const body = await req.json().catch(() => null);
  if (!body || typeof body.rentalId !== "string") {
    return Response.json({ error: "rentalId required" }, { status: 400 });
  }
}
```

### Multipart upload

`request.formData()` works out of the box. Form values are `string | File`, so
narrow them. Validate enum-like fields against the shared constants in
`src/lib/types.ts` (`SLOTS`) before using them in a file path.

```ts
const form = await req.formData();
const file = form.get("file");
const slot = form.get("slot");
if (!(file instanceof File)) return Response.json({ error: "file required" }, { status: 400 });
if (typeof slot !== "string" || !SLOTS.includes(slot as Slot)) {
  return Response.json({ error: "bad slot" }, { status: 400 });
}
const input = Buffer.from(await file.arrayBuffer());
```

Body size: the 1 MB limit you may remember applies to Server Actions, and
`proxyClientMaxBodySize` applies only when a `proxy.ts` exists (we have none).
Route handlers accept full-size phone photos.

### Returning a file

```ts
return new Response(new Uint8Array(buf), {
  headers: { "Content-Type": "image/jpeg", "Cache-Control": "private, max-age=3600" },
});
```

Photo ids are immutable (a retake gets a new id), so caching photo responses is
safe.

### sharp

`sharp` is listed in `serverExternalPackages` in `next.config.ts` so the bundler
leaves the native binary alone. Import it only from server code. Call
`.rotate()` with no arguments before resizing: phone photos carry EXIF
orientation and come out sideways otherwise. The prebuilt binary cannot decode
HEIC, so reject `image/heic` with 415.

### server-only

Anything under `src/lib` that touches the filesystem or the Anthropic key starts
with `import "server-only";`. That makes an accidental import from a client
component a build error instead of a leaked secret or a broken bundle.

## Repo conventions

- Errors are `{ error: string }` with a real status code: 400 bad input, 404
  unknown id, 415 unsupported image, 501 not built yet.
- Route handlers stay thin: parse and validate, call a function in `src/lib`,
  return the result. Logic in `src/lib` can be unit tested without a server.
- Response shapes come from `src/lib/types.ts`. If a route needs a new shape,
  tell the team before changing that file.
- Keep the API table in `README.md` in sync when you add or change a route.
